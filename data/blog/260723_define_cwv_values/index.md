Googleの目的 CWVが良好=高品質なユーザー体験であること CWVが良好なのに遅いみたいな状態がNG

高品質なユーザー体験とは何？

Googleは高品質なユーザー体験とは何かを考えるために 人間の知覚 HCIの研究 を参考にしている

HCIの研究？ ユーザーがフォーカスを失うまでに通常待機する時間は1秒とか でも実際この値ってユーザーにもよるし、状況にもよる 人によるし どんな状況で見てるによる 実際これはChromeの指標データでも実証済み

既存のウェブコンテンツで達成可能！ たとえば、0ミリ秒で表示されたらそりゃ最高やけど 技術的に不可能なのは火を見るより明らか 達成できない値はそもそも指標として成立していない

しきい値候補はCrUXで計測されているフィールドデータで達成可能な数値から選ばれる 少なくとも10%のオリジンが達成している値である必要があるでしょう

逆に指標低の数値は下位10%の数値から選ばれる

デバイス差はどうする？ スマホは遅いことがあるし性能も悪いことがある パソコンは一般的には有線で速いし、性能もスマホよりはイイだろう これらを同じ土俵で戦わせるかという話

まあ、妥協として別々の基準 モバイルは多少我慢とかにしてもイイが、指標としては人間の近くに依存する数値なのでモバイルだろうがパソコンだろうが 基準値は変わらない

パーセンタイルに関して 全体の75%が良い指標でページを触れることを目標にすべき なぜ75%か？ 
1. だいたいほとんどすべてのアクセスで良好な体験を得られる 
2. 95%とかにすると極端なユーザー、コンテキストにまで対応しなければならなくなる 少数のユーザー向けのほとんど効果のない最適化が必要になるから

LCP ユーザーがタスクから注意を逸さずに待てる時間は1秒と言われている 実際の研究ではきっちり1秒なわけではなくて、数百ミリ秒から数秒の間

研究 カードとミラーの2つがよく引用される 両研究ではユーザーが注意を失うまでに待機する時間は0.3秒から3秒の範囲であると示している これはそのままLCPの良好な基準の範囲になってる

達成可能な値を探すために GoogleはCrUXから観測可能 1秒未満 SP3.5% PC6.9% 1.5秒未満 SP13% PC19% 2秒未満 SP27% PC36% 2.5秒未満 SP42% PC51% 3秒未満 SP55% PC64%

これを見ると1秒を満たすのは 1.5であれば10%のページが達成できる さらに75パーセンタイルを考慮すれば1.5と2では達成できず、2.5秒であれば常に達成可能な指標であることがわかる よってLCPの良い指標の閾値は2.5秒となる 低い指標の閾値も同様に決められている

INPは？ 同様に品質と実現可能性を考慮して設計しとる 研究によると視覚的なフィードバックによる遅延が100msであれば、ユーザー操作によって引き起こされた動作と認識されるらしい せやからこの値に近いものがINPの値になるじゃろう

研究その1: Jakob Nielsen
面白い実験がある 球体AとBがある 静止している球体Aに球体Bがコロコロと転がって衝突する そして球体Aがその衝撃で転がり出す 衝突してから100msまでは誰が見ても球体Aの移動は球体Bの衝突によって引き起こされたと感じる 100〜200msまでは意見が混在する 200ms以降は球体Aの移動はBの衝突によって引き起こされと思われなくなるらしい

研究その2: Miller

# Core Web Vitalsのしきい値はどう決まっているか

## CWVとは何のための指標か
CWVは、ユーザーが実際にWebサイトをどう感じるかを表す指標であり、
サイトがユーザーにとって良い状態かどうかを開発者が定性的に把握するためのものである。

- **LCP**: 知覚される読み込み速度
- **INP**: ページの応答性
- **CLS**: 視覚的な安定性

各指標は「良好」「改善が必要」「不良」の3段階に分類され、
**75パーセンタイル**(ページビューの75%以上が良好な体験を得られる状態)が良好の基準として望ましいとされる。

Googleの目的は「CWVが良好=高品質なユーザー体験」を成立させることであり、
「CWVは良好なのに実際は遅い(体感と乖離する)」状態はNGとされる。

## 「高品質なユーザー体験」をどう定義したか
Googleは、人間の知覚に関する研究(HCI研究)を参考にしている。

- 例: ユーザーがフォーカスを失うまでに通常待機する時間は1秒程度、という知見がある
- ただしこの値は人や状況によって変動する。Chromeの実測データでもそれが裏付けられている

### しきい値の決め方: 「研究による理想値」と「現実的な達成可能性」の両立
- 0ミリ秒で表示できれば理想だが、技術的に不可能。**達成できない値は指標として成立しない**
- しきい値の候補はCrUX(フィールドデータ)から選定し、**少なくとも上位10%のオリジンが達成している値**であることを条件とする
- 逆に「不良」の基準は、下位10%の実績値から選ばれる

### デバイス差はどう扱うか
スマホとPCでは性能・回線品質が異なるため、単純に同じ土俵で比較すべきかという論点がある。
妥協案として計測上はデバイス別に扱う場合もあるが、
**基準値自体は人間の知覚に依存するものなので、モバイル/PCで変えない**という立場を取っている。

### なぜ「75パーセンタイル」なのか
1. 75%を基準にすれば、ほとんどのアクセスで良好な体験が得られる
2. 95%等の高い基準にすると、極端なユーザー・極端なコンテキストへの対応が必要になり、
   少数のユーザーにしか効果のない最適化を強いられてしまう

## LCPのしきい値はどう導かれたか
研究によれば、ユーザーがタスクから注意を逸らさずに待てる時間は概ね1秒程度とされる。
ただし正確には「きっちり1秒」ではなく、数百ミリ秒〜数秒の幅がある。

- **参照研究**: Card、Miller
- 両研究とも、ユーザーが注意を失うまでの待機時間は **0.3秒〜3秒** の範囲にあると示しており、
  これがそのままLCPの「良好」基準の範囲に対応している

### CrUXによる達成可能性の検証
| しきい値   | SP(達成率) | PC(達成率) |
| ------ | ------- | ------- |
| 1秒未満   | 3.5%    | 6.9%    |
| 1.5秒未満 | 13%     | 19%     |
| 2秒未満   | 27%     | 36%     |
| 2.5秒未満 | 42%     | 51%     |
| 3秒未満   | 55%     | 64%     |

75パーセンタイル基準で見ると、1.5秒・2秒では達成できないが、
**2.5秒であれば常に達成可能**という結果になる。
→ よってLCPの「良好」のしきい値は **2.5秒** に決定。「不良」側も同様のロジックで決定されている。

---

## INPのしきい値はどう導かれたか
研究によれば、視覚的フィードバックの遅延が100ms程度であれば、
ユーザー操作によって引き起こされた反応だと認識されるとされる。INPのしきい値もこの値に近づく。

### 参照研究3つ

**① Jakob Nielsen(球体の衝突実験)**
静止した球体Aに球体Bが衝突し、Aが転がり出す実験。
- 衝突から**100msまで**: 誰が見てもAの移動はBの衝突が原因だと感じる
- **100〜200ms**: 意見が分かれる
- **200ms以降**: Bの衝突が原因だとは思われなくなる

**② Miller**
キー入力から視覚的フィードバックが表示されるまでの遅延は、
**0.1〜0.2秒以下**である必要があるとされる。

**③ Kaaresoja(タッチスクリーンのボタンタップ実験)**
ボタンタップ後のフィードバック遅延について検証。
- **85ms以下**: 75%の参加者が「フィードバックはタップの影響」と判断
- 感覚的には、100ms以下は「ボタンっぽい」、100〜150msで低下、**300ms以上では体験として良くない**

これら3研究から、「良好」の候補値は **100ms**、「不良」側の候補値は **300ms以上** とみなされた。

### CrUXによる達成可能性の検証
| しきい値 | SP(達成率) | PC(達成率) |
|---|---|---|
| 100ms | 12% | 83% |
| 200ms | 56% | 96% |
| 300ms | 76% | 98% |
| 400ms | 88% | 99% |
| 500ms | 92% | 99% |

75パーセンタイル基準を満たすのは **200ms**。
→ よってINPの「良好」のしきい値は **200ms** に決定。

### 「不良」側の閾値は少し複雑
- 全サイトを対象にすると、300msを超えるのは24%(0〜30%の範囲に収まる)
- しかし**人気サイトに絞ると300ms超えは55%**まで跳ね上がる
  - 理由: 人気サイトは処理が複雑になりがちで、時間がかかりやすい
- 500msなら人気サイトでも24%(0〜30%の範囲)に収まる
→ よってINPの「不良」のしきい値は **500ms** に決定。

## CLSのしきい値はどう導かれたか
CLSは「ページのコンテンツがどれくらいジャンプ(ずれる)か」の指標であり、
LCP/INPと異なり、**参照できる知覚研究が存在しない**。

そのためGoogleは、「どの程度のズレでユーザーが『ページが切り替わった』と感じるか」を独自に調査した。

- **0.15以上**: 常に要素がジャンプしたとみなされる
- **0.1**: ジャンプしたとは感じるが、過度なジャンプとまでは思われない

### CrUXによる達成可能性の検証
| しきい値 | SP(達成率) | PC(達成率) |
|---|---|---|
| 0.05 | 49% | 42% |
| 0.1 | 60% | 59% |
| 0.15 | 69% | 69% |

### なぜ「良好」を0.1にしたのか
フィールドデータ上は0.05でも多くのページが達成できている。
それでも**あえて0.1**を採用している理由は、
レイアウトのズレを開発者側で回避しにくい**エッジケース**が存在すると認識しているため。

- 代表例: **サードパーティ製広告**によるレイアウトシフト
- 「サードパーティ広告がCLSを悪化させない未来」を見込んでの余裕、というニュアンスがある

「不良」側の閾値も同様のロジックで決定されている。
