# はじめに

Webアプリケーション開発者として、絶対に避けては通れないWebブラウザ。それなしには成立しないWebブラウザ。  
そんな大切なものだけれど、どこまで知っていますか？ブラウザのこと。  

Chromeの中の人が書いた素晴らしい書籍を読み進めながら、ブラウザがWebページを表示するまでに何をしているのかを学んでいく。

# ブラウザの役割

ブラウザが誕生してから20年以上が経ち、ブラウザがやっていることは上げていけばキリがない  
しかし、考えてみればブラウザはWebページを構成するファイルを取得して、ファイルを解析しながら画面に描画して、JavaScriptを実行するという3つが大きな役割だ。

- Webクライアントとして
- レンダリングエンジンとして
- JavaScriptエンジンとして

# Webページの取得

URLを入力として受け取る
URLを解析する

URLはUniform Resource Locater、つまり何らかのファイルの場所を指している
さらに、URLにはファイルの場所だけでなくファイルを取得するための方法も示してある
それが、プロトコルだ。代表的にはHTTP/HTTPS、FILE、MAILTOなどがある。

指定の取得方法で示された取得場所からファイルを取得するのが1つ目の仕事だ。

# 画面への描画 その1

ファイルが取得できたのだから早速画面に描画しよう！  
（本当は取得から描画開始までに色々なことをやっているけど、まずが動くものが見たい）

では、どのようにしてOS上にブラウザを表示すればいいだろうか？というところから考えないといけない。これにはOSの力を存分に借りることになる。
以下のようなループを繰り返している。

1. プログラムはOSに新しいウィンドウを表示してくれるように頼む
	1. デスクトップOSがウィンドウを表示する
2. プログラムから表示されたウィンドウにコンテンツを描画する
	1. デスクトップOSがウィンドウに表示する

イベントがあった場合は逆になる

1. イベント（マウスのクリックやスクロール）があれば、デスクトップOSがプログラムに通知する
2. プログラムがイベントに応じたコンテンツをウィンドウに描画する
3. デスクトップOSがウィンドウに表示する

通常ブラウザはこのような「イベントループ」パターンでデスクトップOS上にWebブラウザを表示している。

# HTMLの解析

HTMLの解析ではやること多い

1. HTMLファイルを解析してHTMLツリーにする
2. HTMLツリーを描画のためにレイアウトツリーに変換する
3. そのままじゃ見栄えが悪いので、レイアウトツリーにスタイルを付与する
4. スタイルはブラウザのデフォルトだけではそっけないのでCSSファイルで提供されることもある

URLを頼りにファイルを取得すると大抵HTML形式のテキストファイルを取得することになる。  
これを元にWebブラウザの画面にコンテンツを描画していくわけだが、まずは画面描画の下準備としてHTMLを解析してツリー構造にしていく。
ここで作成したツリー構造がHTMLツリーやDOMツリーなんて呼ばれたりする。


# CSSの解析

CSSは重要だ
元々はHTMLファイルのスタイルはタグでやっていた
早々にタグでやることに限界が来た（多分めちゃくちゃ管理しづらかったんだと思う）

HTMLファイルはコンテンツ内容をコンテンツの見栄えはCSSファイルにまとめればいいんじゃね？となった。

CSSファイルを解析しないといけないねとなった。
CSSファイルの解析大変だがHTMLファイルの解析と大差ない。
解析というのは地道に一つずつこなしていくだけだ。

CSSではセレクタとスタイル本文部分の解析がメインだろう。

```css
p a {
	color: blue;
}
```

ルールに応じて、このセレクタとボディ部分を解析してCSSツリーに展開していく。
どの要素にどのスタイルを与えるかが決まったら、レイアウトツリーを走査して、一つずつスタイルを与えていく。

# 画面への描画 その2

その1では忘れていた
WebブラウザにはURLを入力する欄 や 戻るボタン などの部品が必要だった
これがないと快適なブラウジングができない

実はWebブラウザの画面以外の部品のことをChromeというらしい。これはWebブラウザのChromeという命名にも影響を与えたらしい。

さらに、リンクをクリックしたときに画面を遷移する処理も必要だ。
さらにさらに、HTMLにはフォーム要素がある。。。。
まだまだやることがありそうだ。
