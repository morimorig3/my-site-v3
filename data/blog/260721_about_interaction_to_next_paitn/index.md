INP=interaction to next paintはEvent Timing APIのデータで応答性を評価する
ユーザーがページで行なったインタラクションのレイテンシをモニタリングして
すべてのインタラクションが下回った1つの値を報告する←？
INPが低いということはページが全てのユーザーインタラクションまたは大部分に対して一貫して迅速に応答できていると言える
つまり、ユーザーの操作に素早く答えるページがINPが優れているということ

CLSやLCPはページの初期読み込み時にはもちろん重要だが
実際ユーザーがページに費やす時間の90%は読み込み完了後の話だ
そこを評価するのがINPである

応答性が高いってどういうこと？
ページが操作に素早く反応する
たとえば、カードに追加したらカートアイコンに1と表示される、ナビゲーションをタップしたらメニューが開く、ログインボタンを押したらユーザー名が表示されるなど

もちろんログインのような確認事項が多い操作が他の操作よりも時間がかかるのは当然だけど
それと画面を固まらせるのは違う
つまり、ログインで時間がかかるならローディングを表示して視覚的なフィードバックをユーザーに与えれば良い

INPの目的はネットワーク取得や他の非同期操作によるUIの更新などの最終的な処理完了の時間を測定することではなくて、次のペイントがブロックされている時間を測定することである
視覚的なフィードバックが遅れてしまうとユーザーにとってはページが遅い・固まったと感じさせてしまう可能性がある
INPはユーザーエクスペリエンスを測定するために開発された

あらためてINPとは
ページアクセスの全期間中に発生するすべての
- クリック
- タップ
- キーボード操作のレイテンシ
をモニタリングしてユーザーインタラクションの全体的な応答性を評価するための指標

すべてのインタラクションを記録してもっとも長いものがINPとされる
どうしても外れ値が発生することがあるので50回を超えるインタラクションがある場合はもっとも長いレイテンシの値を1つスキップする

インタラクションとは？
ユーザーの1操作
もっと技術的に言えば、ユーザー操作中に発生するイベントハンドラのグループ
たとえば、タップ操作をすれば`pointerup`, `pointerdown`, `click`などのイベントが発火する
これらはJavaScriptで検知可能

では、インタラクションのレイテンシとは？
インタラクションを開始してからブラウザが次にフレームをペイントできるようになるまでの間

INPの数値について
75パーセンタイルを測定する閾値を利用すべき
半分より少し悪いくらいの値がGoodの指標であるべきで
つまり、75%の人は良い体験をもたらすべき

INPが200ms以下であればGoodと言える
200~500ms以下は改善すべき
500ms以上はうんこ

インタラクションってこんな感じ
![[whats-in-an-interaction.svg|697]]
クリックして何がを描画するという一連のイベント
1. クリックする（Input received）
2. イベントが発生するまで（Input delay）
3. イベント処理中（Precessing duration）
4. ブラウザが描画する（Frame presented）
この一連の長さがINPで、INPが低いということはユーザーがどんな操作をしても
サクサクと動くページであると言える

```
処理時間 = 入力遅延 + 処理時間 + 表示遅延
```

あくまでもユーザーが体感する速度を計測するのが目的なので
- マウスクリック
- 画面タップ
- キーボード入力のような
ユーザーからのアクションが必要なインタラクションのみを計測対象とする

ホバーやズームやスクロールはINPでは観測しない

INPとFID（First Input Delay）の違いは？
まずINPはFIDの後継指標
FIDはその名の通りページの最初のインタラクションのみを計測対象にしていた


FIDはページを読み込んで最初のインタラクションの入力遅延のみを計測対象
INPは処理時間を包括的にかつ最初だけでなく全体を計測対象とする

FIDは初期読み込みにフォーカスされている一方で
INPはページ全体の応答性を評価する

こんな時はINPが計測できない
- クリック、タップ、キーボード操作をしていない
- ボットでアクセス

測定に関して
本番で行え
RUMツールではINPの値だけじゃなくてきっかけになった特定のインタラクションを教えてくれる
